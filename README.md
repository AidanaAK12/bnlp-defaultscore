# Прогнозирование Кредитного Дефолта для BNPL-сервиса (Credit Scoring) 💳📊

Проект посвящен разработке модели машинного обучения для оценки кредитного риска клиентов BNPL-сервиса («Buy Now, Pay Later»). На основе исторических и финансовых данных о пользователях модель классифицирует их по трем уровням риска дефолта: **Low (Низкий)**, **Medium (Средний)** и **High (Высокий)**.

## 🎯 Бизнес-задача
Снизить финансовые потери финтех-платформы за счет точного выявления потенциальных неплательщиков (класс `High`) на этапе оформления рассрочки, минимизируя при этом отказы надежным клиентам (класс `Low`).

## 📈 Пошаговое описание реализации проекта

### Шаг 1. Разведочный анализ данных (EDA) и Предобработка
* **Анализ структуры:** Исходный датасет содержит `10 000` строк и `11` признаков. Полные дубликаты отсутствуют.
* **Заполнение пропусков:** В признаках `Income_USD` и `Credit_Score` обнаружено по 3% пропусков. Так как данные распределены несимметрично и содержат выбросы, пропуски были успешно заполнены медианными значениями.
* **Изучение дисбаланса:** Выявлен сильный дисбаланс целевой переменной `Default_Risk` (около 88% — Low, ~7% — Medium, ~5% — High). Это учтено при обучении с помощью балансировки весов.
* **Ключевые инсайты:**
  * Обнаружена сильная линейная корреляция между количеством активных кредитов (`Total_BNPL_Active_Loans`) и общим долгом (`Total_BNPL_Debt_USD`).
  * Чем выше риск дефолта, тем ниже кредитный рейтинг (`Credit_Score`) и выше общая сумма долга клиента.

### Шаг 2. Разработка Baseline-модели
* Данные разделены на обучающую и тестовую выборки в соотношении 80/20 с применением стратификации для сохранения пропорций классов.
* Создан пайплайн предобработки данных: числовые признаки масштабированы с помощью `StandardScaler`, категориальные — закодированы через `OneHotEncoder`.
* В качестве базовой модели (Baseline) обучена **Логистическая регрессия** с балансировкой классов. Модель показала `Accuracy = 0.8785`, однако из-за дисбаланса классов метрика `F1-score` для класса Medium составила всего `0.4670`.

### Шаг 3. Оптимизация и Улучшение моделей
Для повышения качества классификации редких классов (`Medium` и `High`) были предприняты следующие шаги:
1. **Подбор гиперпараметров (GridSearchCV):** Настройка регуляризации для Логистической регрессии подняла общую точность до `92%`.
2. **Проектирование признаков (Feature Engineering):** Создан новый синтетический признак `Debt_to_Income` (соотношение долга к доходу), который значительно повысил разделяющую способность моделей.
3. **Ансамблевые методы:** Обучены модели **Random Forest** и градиентный бустинг **XGBoost** с учетом весов сэмплов для компенсации дисбаланса.

## 📊 Результаты экспериментов

В ходе работы были сопоставлены 6 конфигураций моделей. Качество оценивалось по метрике `F1-Macro`, так как она одинаково важна для всех классов:

| Модель | Accuracy | F1 Macro | F1 High | F1 Medium | F1 Low |
| :--- | :---: | :---: | :---: | :---: | :---: |
| Logistic Regression Baseline | 0.8785 | 0.7402 | 0.8152 | 0.4670 | 0.9385 |
| GridSearch Logistic Regression | 0.9200 | 0.7506 | 0.7615 | 0.5231 | 0.9673 |
| Logistic Regression (+FE) | 0.9510 | 0.8455 | 0.8818 | 0.6756 | 0.9790 |
| Random Forest Baseline | 0.9595 | 0.8510 | 0.8868 | 0.6825 | 0.9836 |
| Grid Search Random Forest | 0.9600 | 0.8579 | 0.8679 | 0.7208 | 0.9849 |
| **XGBoost (Лучшая модель)** | **0.9630** | **0.8766** | **0.9014** | **0.7439** | **0.9846** |

**Итог:** Модель **XGBoost** в сочетании с Feature Engineering показала наилучшие результаты. Она успешно справляется с дисбалансом, демонстрируя высокую точность как для надежных клиентов (`F1 Low = 0.9846`), так и для группы высокого риска (`F1 High = 0.9014`).
